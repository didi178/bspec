# BSpec

> **Behavior is the Source.**

BSpec is an early-stage open-source research project about building software when implementation code is cheap, abundant, and increasingly generated by AI.

It is not a finished language, compiler, or production toolchain. The project exists to test a hypothesis: if humans stop routinely reading generated code, then implementation code can no longer be the primary source of truth. The durable source may need to become an explicit, inspectable description of behavior.

## The problem

AI sharply reduces the cost of producing implementation code. That changes more than developer productivity:

- generated implementations may become too large or too disposable for humans to review line by line;
- code review may cease to be a reliable trust boundary;
- intent, constraints, and observable behavior must survive across many regenerated implementations;
- correctness needs evidence that is independent from the system that produced the code.

BSpec explores what software development looks like when behavior or specification is the source of truth and implementation code is a derived artifact.

## Working model

The initial model separates three responsibilities:

1. A **builder agent** reads the behavior specification and creates an implementation.
2. An **adversary agent**, operating independently, tries to falsify the implementation: finding counterexamples, violating invariants, and exposing behavior the specification left ambiguous.
3. A conventional **compiler and toolchain** turns the implementation into an executable artifact.

The builder and adversary should not merely agree with each other. Their separation is intended to create useful tension and stronger evidence about whether the resulting software behaves as specified.

```text
behavior / specification
       |             \
       v              v
 builder agent   adversary agent
       |              |
       v              v
 implementation <--- challenges
       |
       v
 conventional compiler / toolchain
       |
       v
 executable artifact
```

This is a research sketch, not yet an architecture or security guarantee.

## What BSpec might become

It is deliberately unknown whether this work requires:

- a new human-facing language;
- a semantic intermediate representation;
- a graph model of behaviors, constraints, evidence, and dependencies;
- a methodology layered on existing languages and tools;
- or some combination of these.

The project should earn an answer through experiments rather than assume one at the outset.

## Status and participation

BSpec is exploratory. Definitions, formats, and architecture are expected to change. There is no stable syntax, compatibility promise, or claim that BSpec should replace conventional programming languages.

Contributions are welcome as experiments, counterexamples, critiques, and proposals. A useful contribution should make its assumptions explicit and explain what evidence would confirm or reject them.
